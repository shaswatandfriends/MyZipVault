## Part A: Checklist Reuse Logic

**File**: `src/app/api/recruiter/send-request/route.ts`

### Changes:
1. **Fetched checklist template name** (lines 110-115) — queries `checklistTemplate` to get the name for the reuse message.
2. **Added existing active response check** (lines 117-160) — queries `candidateChecklistResponse.findFirst` with filters:
   - `candidate_user_id` matches
   - `checklist_template_id` matches
   - `status` is `'active'`
   - `valid_until` is >= current date (still valid)
3. **Reuse path** (when existing response found):
   - Creates a new `ChecklistRequest` with `status: 'completed'`, `completion_pct: 100`, linking to the existing response via `candidate_response_id`
   - Creates a `ConsentShare` linking the existing response to the requesting client, with 30-day expiry
   - Returns early with `reusedExistingResponse: true` and descriptive message
